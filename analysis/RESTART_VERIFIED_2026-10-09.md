# Координаты после перезапуска: проверено

На сборке com.proxima.dfm 1.202.37117.5601 переход PID 24536/start493421 → PID 21490/start718694 подтверждает новый процесс, а не только новый матч. В новом процессе база libUE4 — 0x6FE723B000. Runtime state самостоятельно найден как 0x7210D32000.

Ключ независимо восстановлен из свежих записей как **0x53D1D34B**, совпавший с предыдущим процессом. В этом перезапуске ключ сохранился. Это опровергает утверждение о его обязательной смене при каждом запуске, но не доказывает постоянство ключа. Более ранний процесс PID22846 был проверен с другим ключом 0x765D0871.

`recover_live_session.py` завершил поиск состояния, два захвата, полный поиск кандидатов, проверку по слотам и второй выборке, затем третий захват найденным ключом. Старый адрес и ключ в эту команду не передавались. Процедура исследовательская, требует активных данных матча и пока не подключена к установленному оверлею.

Проверки нового процесса:

- 24 реальных payload совпали с текущим нативным ARM64-распаковщиком. Код проверен по действующему dispatch и прямому BL к распаковщику; случайная копия из executable-региона не использовалась.
- C++-декодер Android и Python побитно совпали на 30 векторах из двух снимков, включая случай отключённого дубликата записи.
- Расчётная дистанция живого союзника **181.28 м**, HUD **181 м**. Pawn/PlayerState связаны в обе стороны, DeadInfo=0. Курс камеры **22.47°**, компас **22°**. В процессе получения скриншота сняты 23 чтения памяти; положение союзника для этого сравнения стабильно.
- Пересобранный standalone Android reader выдал 10/10 стабильных кадров `ok`, с валидной камерой, без ошибок и с декодированным живым удалённым игроком в каждом кадре. APK/оверлей не переустанавливался.

Исправлено: отключённые guard-записи исключаются до проверки уникальности хеша; несколько действующих записей по-прежнему отклоняются. Заголовки читаются быстрым пакетом непосредственно перед снимком и после него; проверяются время запуска процесса, World/GameState, roster, указатель записей и соли. Запросы native page helper теперь используют отдельные временные файлы, предотвращая смешивание параллельных запросов.
